# Hash (雜湊)

---

## 關於 Hash

### Hash 是甚麼 (What)?
* 是一種資料結構，儲存 **Key-Value** 配對的集合。
* **Key-Value (鍵值對)**: 可以想像成字典中的字母 (key)，在對應的字母中可以找到你想找的單字。
* **Definition**: A data structure that stores key-value pairs by using a hash function to compute an index into an array of buckets.
  (bucket which stores the key-value pairs,not just value)

### Hash 甚麼情況會用到 (When)?
* 像是加密 (`encryption`) 時，可以透過 hash 把你的 `key`，透過 `hash function` 的設計去加密成 `index`。

### Hash 要怎麼運用 (How)?
* **Hash function 的設計**:
    1.  良好的 Hash function 關乎到整個資料的 **效率** 以及 **分布的均勻性**。
    2.  **m 值 (Hash table 的大小)** 的設定: 通常會設定為 **質數**，可以讓資料均勻分配，進而減少衝突的發生。
* **Collision (衝突) 的處理**:
    1.  Chaining (鏈結法)
    2.  Open Addressing (開放定址法)
    3.  Composite Hashing
    4.  Hash Refinement

### Hash 的優缺點 (Pros/Cons)
* **Pros**:
    1.  **Fast lookups**: $O(1)$ average case，省去了查找資料的時間，快速篩選候選項。
    2.  優異的時間複雜度 (詳見下方表格)。
* **Cons**:
    1.  發生衝突 (`Collision`) 時，運作效率上會變差 (**詳情請看下方敘述**)。

## Time Complexity (時間複雜度)

### Chaining (鏈結法)
※ Load Factor $\alpha = \frac{N}{M}$

| Operation | Best Case | Average Case | Worst Case |
| :--- | :--- | :--- | :--- |
| **Insertion** | $O(1)$ | $O(1+\alpha)$ | $O(N)$ |
| **Search** | $O(1)$ | $O(1+\alpha)$ | $O(N)$ |
| **Deletion** | $O(1)$ | $O(1+\alpha)$ | $O(N)$ |

### Open Addressing (開放定址法)
※ Load Factor $\alpha = \frac{N}{M}$

| Operation | Best Case | Worst Case |
| :--- | :--- | :--- |
| **Insertion** | $O(1)$ | $O(N)$ |
| **Search** | $O(1)$ | $O(N)$ |
| **Deletion** | $O(1)$ | $O(N)$ |

## 運作流程 (Operation)

### 基本操作
* `key` -> **Hash Function (Convert key to index)** -> `index` -> `value`

### Hash Function
* **Definition**: A function that converts a key into an index.
* **Property**:
    1.  **Efficiency**: computed quickly.
    2.  **Deterministic**: same key -> same index.
    3.  **Diverse**: spread the key evenly across the indices.
* **Implementation**:
    1.  **Division method**:
        $$h(k) = k \bmod m$$
    2.  **Multiplication method**:
        $$h(k) = \lfloor m (k A \bmod 1) \rfloor$$
        * 其中 $0 < A < 1$，通常取 $A \approx 0.618$ (黃金比例的小數部分)。
    3.  **Folding method**:
        * Split key into several parts and sum them up.
        * Example: if $k = 123456$, then maybe $h(k) = (123 + 456) \bmod m$.
    4.  **String Hashing**:
        * By `polynomial rolling hash`.
        * $$h(s) = \left( \sum s[i] \cdot p^i \right) \pmod m$$

### Collision (衝突)
* **Normal situation**: Every pair of key-value is unique, only have one value for one key.
* **Definition**: There are several different keys which mapped by hash function to the same index in the table.
* **Solution**:

#### 1. Chaining (鏈結法)
* **Definition**: 運用 `Array` + `Linked List` 的設計，使每個 index 可以儲存多個 value。
* **Pros**:
    1.  運用到 Linked List 的特點: 插入/刪除的 Time Complexity 都是 $O(1)$ (已知節點位置的情況下)。
    2.  **Dynamic size**: 透過 `Rehashing` 的設計，調整 `M` 的大小，以避免 Collision 的發生。
* **Cons**:
    1.  實作較為複雜，尤其 Linked list 涉及對於指標的管理。
    2.  **Memory Overhead**: 透過不斷的 `realloc`/`malloc`，除了會不斷地對記憶體進行操作，實際上也會比 Array 的速度來的慢 (Array is directly access)。
    3.  **Collision**: 當衝突產生時，如果 Linked list 的長度過長，會影響到插入/刪除/搜尋的效率 (Worst Case: $O(N)$)。

#### 2. Open Addressing (開放定址法)
* **Definition**: 針對 `hash function` 的設計，使得 probing 的運作更有分佈性，進而減少衝突的發生。
* **種類**:
    1.  **Linear Probing**:
        * Formula: $index = (h(k)+i) \bmod m$
        * **Pros**: Simple.
        * **Cons**: **Primary Clustering** (當發生衝突時，會**連續地**往下尋找空的儲存格，形成巨大集合，影響效率)。
    2.  **Quadratic Probing**:
        * Formula: $index = (h(k) + C_1 \cdot i^2 + C_2 \cdot i) \bmod m$
        * **Pros**: 資料的分佈更加均勻。
        * **Cons**: **Secondary Clustering** (當發生衝突時，雖然是**非連續**跳躍，但同樣 hash 值會走同樣的路徑)。
    3.  **Double Hashing**:
        * Formula: $index = (h_1(k) + i \cdot h_2(k)) \bmod m$
        * **Pros**: 資料的分佈更加均勻。
        * **Cons**: 涉及到兩個 `hash function` 的設計，運算速度較慢。
    4.  **Primary Clustering & Secondary Clustering差別**
        * Primary Clustering:不同起點也會撞在一起，形成連續區塊
        * Secondary Clustering:只有同起點才會走同路徑

#### 3. Composite Hashing
* **Definition**: 考量更多資料的屬性 (attribute) 以及類別 (classification)，進而設計出更有效的 `hash function`。

#### 4. Hash Refinement
* **Definition**: 對 `hash function` 進行優化，進而減少衝突的發生。

## Abstract Data Type (ADT)

### Vocabulary
* `Create(D, m)`: Create a hash table 'D' with size 'm'.
* `Search(D, k)`: Search for key 'k' in hash table 'D'.
* `Insert(D, k, v)`: Insert key 'k' with value 'v' into hash table 'D'.
* `Delete(D, k)`: Delete key 'k' from hash table 'D'.

## Comparison (Static vs Dynamic)

| Feature | Static Hashing | Dynamic Hashing |
| :--- | :--- | :--- |
| **Size** | `Fixed` | `Dynamic` |
| **Load Factor** | $\alpha = \frac{N}{M}$ (higher -> more collision) | Remains efficient |
| **Hash Function** | `Constant` | `Adaptive` |
| **Rehashing** | Entire table must be rebuilt | Reallocate memory to new table |
| **Implementation**| `Simple` | `Complex` |
| **Best Use Case** | Fixed data set / Simple needs | Dynamic data set / Complex needs |
